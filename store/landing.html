Umbra
Browser Control for AI Agents

Drive your signed-in Chrome from any LLM.

I built Umbra because I wanted to drive my own signed-in Chrome from whatever LLM I'm working with, not just Claude in Chrome. Same idea, model-agnostic: you pair it with a local key, point any MCP client at it, and it runs your browser in the background without stealing focus. Nothing leaves your machine.

Local loopback only No focus theft Per-session tab ownership MCP-native No account, no telemetry
A local agent drives your signed-in Chrome while you keep working.

How it works

Umbra is two pieces that pair on a key you generate yourself: a Chrome extension that owns every browser action, and a small companion server on your machine that exposes a browser tool surface to your MCP client. They talk over a WebSocket on 127.0.0.1, authenticated with an HMAC of your key. The extension does nothing until that pairing exists.

  • Model-agnostic. Any MCP client works. You are not tied to one assistant.
  • It stays out of your way. Actions run in the background, on the tabs a session owns, without pulling Chrome to the front.
  • Owned tabs only. A tab you opened yourself cannot be read, clicked, or closed by any agent.
  • Local by construction. The only host it can reach is a program on your own machine. There is no server of ours for it to talk to.

Get it

Install the extension from the Chrome Web Store, then clone the open-source companion server and pair it:

git clone https://github.com/RobertJLora/umbra
cd umbra/mcp-server && npm install && node cli.js pair

That prints the config block to drop into your MCP client. Full setup and the privacy details are linked below.
